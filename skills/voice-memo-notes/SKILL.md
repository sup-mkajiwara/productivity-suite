# ボイスメモ → 会議メモ（Voice Memo Notes）

Mac のボイスメモで録音した音声を whisper.cpp でローカル文字起こしし、
**要約（議題・決定事項・ToDo）＋文字起こし全文** の Markdown を指定フォルダに作成します。

音声は外部に送信せず、すべてローカルで処理します。

## 実行方法

```
/voice-memo-notes                      # 未処理の録音をすべて処理
/voice-memo-notes ~/path/to/audio.m4a  # 特定の音声ファイルを処理
/voice-memo-notes ~/path/to/folder     # 特定フォルダ内の録音を処理
```

launchd による自動監視も可能です（`scripts/install.sh` で登録）。

---

## 設定ファイル

`~/.claude/config/voice-memo-config.json` を読み込みます
（環境変数 `VOICE_MEMO_CONFIG` で場所を変更可能）。

| 項目 | 説明 |
|------|------|
| `source.mode` | `export`（書き出しフォルダを監視）/ `voicememos`（ボイスメモ本体を直接監視） |
| `source.watch_dir` | `export` モードで監視するフォルダ |
| `source.voicememos_dir` | `voicememos` モードで読むフォルダ（フルディスクアクセスが必要） |
| `source.min_seconds` | この秒数未満の録音は無視する |
| `processed.archive_dir` | 処理済み音声の移動先（空なら移動しない） |
| `output.dir` | **会議メモ Markdown の出力先** |
| `output.filename_format` | ファイル名の形式。`{date}` `{time}` `{title}` が使える |
| `output.include_full_text` | 文字起こし全文を md に含めるか |
| `output.tags` | frontmatter に付けるタグ |

**フォルダは固定ではありません。** 設定ファイルの値が既定になり、
Skill 実行時の引数や下記の明示指示で上書きできます。

---

## 手順

### 1. 入力の判別

このメッセージに **文字起こしテキストのパスが渡されているか** を確認する。

- **渡されている場合**（launchd 経由の自動実行）
  → 文字起こしは完了済み。手順 2 へ進む。
- **渡されていない場合**（`/voice-memo-notes` を手動実行）
  → 先に文字起こしを実行する：

  ```bash
  ~/.claude/scripts/voice-memo-transcribe.sh [対象パス]
  ```

  - このリンクは `scripts/install.sh` が作成する。**存在しない場合はセットアップ未完了**なので、
    `scripts/install.sh` の実行を案内して終了する（自分でインストールを試みない）。
  - 標準出力に `文字起こしtxt <TAB> 音声パス <TAB> 長さ(秒) <TAB> 録音日時` が1件ずつ出る。
  - 出力が空なら「新しい録音はありません」と報告して終了する（ファイルは作らない）。
  - 依存コマンドやモデルが無いというエラーが出た場合も、`scripts/install.sh` を案内して終了する。
  - 文字起こしは録音の長さに比例して時間がかかる（1時間の録音で数分程度）。

### 2. 文字起こしテキストを読む

Read ツールで文字起こし .txt を読み込む。長い場合も全体を読む。

### 3. 内容を理解して会議メモを組み立てる

whisper の出力は**話者の区別がなく、誤変換も含まれる**前提で扱う。

- 明らかな誤変換は文脈から補正して要約に反映する（全文はそのまま残す）
- 会議のタイトルは内容から簡潔に付ける（例: `週次定例`、`A社向け提案レビュー`）
  - ファイル名に使うため、`/` `\` `:` などファイル名に使えない文字は避ける
- 会話が雑多で会議と判断できない場合は、タイトルを `音声メモ` とし、要約は要点の箇条書きにする

### 4. Markdown を出力先に書き込む

`output.dir` に、`output.filename_format` に沿ったファイル名で **Write** する。
既定は `{date}_{title}.md`（例: `2026-08-03_週次定例.md`）。

同名ファイルが既にある場合は、末尾に `-2`, `-3` … を付けて別ファイルにする
（**既存の会議メモを上書きしてはいけない**）。

形式:

```markdown
---
date: YYYY-MM-DD
time: HH:MM
duration: MM分
source: 元の音声ファイル名
tags: [会議メモ]
---

# YYYY-MM-DD <会議タイトル>

## 概要

3〜5行で、何の会議で何が決まったのかを要約する。

## 議題・論点

- **論点1** — どういう議論だったか
- **論点2** — どういう議論だったか

## 決定事項

- 決まったこと（決まっていない場合は「決定事項なし」と書く）

## ToDo

- [ ] やること（担当者が話に出ていれば「担当: 名前」を付ける／期限が出ていれば付ける）

## 保留・次回確認

- 結論が出なかった点、次回に持ち越した点

---

## 文字起こし全文

（`output.include_full_text` が true の場合のみ。文字起こしテキストをそのまま貼る）
```

- 該当する内容が無いセクションは、見出しを残して「なし」と書く（セクション自体は消さない）
- `duration` は渡された秒数を分に換算して記載する（例: `2712` → `45分`）

### 5. 結果を報告する

作成したファイルのパスと、決定事項・ToDo の件数を簡潔に報告する。

```
✅ 会議メモを作成しました
   <出力パス>
   決定事項 N件 / ToDo N件
```

複数件処理した場合は、1件ごとに1行で列挙する。

---

## 注意事項

- **文字起こしは要約の根拠であり、聞き取り違いが必ず含まれる。**
  断定できない箇所は要約に「（要確認）」を付ける。数値・金額・日付・固有名詞は特に注意する。
- 会議には**取引先名・担当者名・社外秘の情報**が含まれる。
  作成する Markdown はローカルの出力先フォルダのみに保存し、
  外部サービスへの送信・チャットへの長文転記は行わない。
- 元の音声ファイルは削除しない（アーカイブへの移動は `transcribe.sh` が行う）。
- 出力先フォルダが存在しない場合は作成する。
- 文字起こしに失敗した音声は処理済みとして記録されないため、次回自動的に再試行される。

---

## セットアップ

初回のみ以下を実行します（Homebrew が必要）。

```bash
skills/voice-memo-notes/scripts/install.sh
```

- `whisper-cpp` と `ffmpeg` を導入
- 文字起こしモデル `ggml-large-v3-turbo.bin`（約 1.6GB）をダウンロード
- 設定ファイルとフォルダを作成
- launchd による自動監視を登録（任意）

詳細は [docs/VOICE_MEMO.md](../../docs/VOICE_MEMO.md) を参照してください。
